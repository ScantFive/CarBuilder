# Car Body Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Отдельное окно «Кузов», где кузов собирается из деталей и получает точки крепления, которые в редакторе каркаса соединяются балками с узлами; кузов даёт массу и коллайдеры в заезде.

**Architecture:** Pure-модель кузова (`src/model/body.ts`: типы, вершины, площадь, масса) и pure-операции (`src/body/bodyOps.ts`) расширяют существующую модель машины (version 2). Экран `BodyEditor` (Three.js + TransformControls) работает с той же `CarDesign`, что и редактор каркаса; `main.ts` переключает три экрана. Балки ссылаются на id узла или точки крепления через общий резолвер `endpointPos`.

**Tech Stack:** TypeScript, Three.js (`TransformControls`, `OrbitControls`), Rapier3D, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-09-car-body-design.md` (дополняет `2026-10-08-carbuilder-design.md`)

## Global Constraints

- Формат машины `version: 2`; `parseCar` принимает 1 и 2, на выходе всегда 2.
- Формы: `box | wedge | cylinder | sphere | wing`. Стороны 0.02..4 м. Центр детали: |x| ≤ 1.6, 0 ≤ y ≤ 2, |z| ≤ 3.5.
- Не больше 60 деталей и 16 точек крепления.
- Масса оболочки 6 кг/м². Балки 8 кг/м (как раньше).
- Размеры по умолчанию: box 1×0.05×1, wedge 1×0.4×0.8, cylinder 0.6×0.3×0.3, sphere 0.5×0.5×0.5, wing 1.6×0.04×0.4; позиция (0, 0.6, 0); цвет `#d33a2c`.
- Привязка гизмо: перемещение 0.05 м, поворот 5°. Точки крепления округляются до 0.01 м.
- Симметрия: порог центра |x| < 0.05; зеркало x → −x, ry → −ry, rz → −rz; пара — совпадение позиции (допуск 0.01) и формы.
- Подвеска в покое 0.3 м (`SUSPENSION_REST`) — теперь экспортируется из `src/model/physicsProps.ts`, `sim/vehicle.ts` импортирует её оттуда.
- Тексты ошибок дословно: `"Кузов не прикреплён к каркасу"`, `"Кузов ниже колёс — заденет землю"`, `"Слишком много деталей кузова (максимум 60)"`, `"Слишком много точек крепления (максимум 16)"`.
- Pure-модули не импортируют `three`/`@dimforge/*`.

## Review Focus

1. Машина version 1 в localStorage или из старого файла → открывается без кузова, ничего не теряется (тест в Task 1).
2. Удаление точки крепления, к которой ведут балки → балки удаляются вместе с ней, машина остаётся валидно парсящейся (тест в Task 3).
3. Деталь с x≈0 при симметрии → без дубликата; зеркальная деталь получает отражённый поворот (тест в Task 3).
4. Повёрнутая деталь, уходящая углом ниже колёс → проверка учитывает поворот (вершины), а не только центр (тест в Task 2).
5. Импортированный файл с балкой на несуществующую точку крепления или с неизвестной формой детали → понятная ошибка импорта (тест в Task 1).

### Task 3: Операции кузова и балки к точкам крепления

**Files:**
- Create: `src/body/bodyOps.ts`, `tests/body/bodyOps.test.ts`
- Modify: `src/editor/symmetry.ts`, `tests/editor/symmetry.test.ts`

**Interfaces:**
- Consumes: Task 1, 2.
- Produces (`bodyOps.ts`, все pure, возвращают новую `CarDesign`, создают `body`, если был `null`):
  - `addPart(c, shape, mirror): { car: CarDesign; id: string }` — по умолчанию из Global Constraints; при лимите 60 возвращает `c` и `id: ''`.
  - `updatePart(c, id, patch: Partial<Omit<BodyPart,'id'>>, mirror)` — кламп размеров/позиции; зеркальной паре — отражённые позиция/поворот, те же size/color/shape.

  - `addMount(c, p: Vec3, mirror)`, `deleteMount(c, id, mirror)` — удаляет балки к точке.
  - `mirrorPartOf(c, id): string | null`, `mirrorMountOf(c, id): string | null`.
- Produces (`symmetry.ts`): `mirrorOf` работает и для точек крепления; `addBeam`/`deleteBeam` принимают id точек крепления; `deleteNode` не трогает точки.
